Automatisation d'Infrastructure avec Terraform & Ansible

Semestre 5 • Projet DevOps

Contexte & Objectifs

Ce projet vise à concevoir une solution d'automatisation complète permettant de déployer, tester et supprimer un environnement applicatif de manière reproductible, fiable et entièrement automatisée.

L'objectif principal est de pouvoir lancer un seul script d'installation sur une machine vierge, sans dépendances préalables, pour installer les outils nécessaires, déployer l'infrastructure, configurer les services et vérifier leur bon fonctionnement.

Technologies & Outils

  • Docker (Conteneurisation)
  • Terraform (Infrastructure as Code)
  • Ansible (Configuration Management)
  • Bash (Orchestration)
  • Nginx (Serveur web)
  • PostgreSQL (Base de données)
  • Linux (Ubuntu/Debian)

Architecture du Projet

L'architecture repose sur une séparation claire des responsabilités :

  • Bash : Orchestration globale (vérification des prérequis, génération des fichiers, lancement des déploiements, tests automatiques)
  • Terraform : Définition de l'infrastructure et déclenchement d'Ansible via provisioner
  • Ansible : Configuration des services Docker (réseau, volumes, conteneurs Nginx et PostgreSQL)

Fonctionnement du Script d'Installation

Étapes Automatisées

  1. Vérification des droits administrateur - Contrôle des permissions sudo nécessaires
  2. Installation automatique des outils - Docker, Terraform, Ansible et dépendances (installation idempotente)
  3. Génération dynamique des fichiers - Inventaire Ansible, playbook et configuration Terraform créés automatiquement
  4. Déploiement des services - Initialisation Terraform puis exécution Ansible pour déployer réseau, volumes et conteneurs
  5. Tests automatiques - Vérification de l'état des conteneurs, tests HTTP (Nginx) et SQL (PostgreSQL)

Script de Désinstallation

Le script uninstall_td4_ansible.sh permet un nettoyage complet et ciblé :

  • Destruction de l'infrastructure via terraform destroy
  • Suppression des ressources Docker créées (conteneurs, réseau, volume)
  • Suppression du dossier projet
  • Désinstallation de Terraform et Ansible

⚠️ Docker lui-même n'est pas supprimé, seules les ressources du projet sont nettoyées.

Résultats Obtenus

  • Déploiement automatisé fonctionnel sur plusieurs machines
  • Environnement reproductible et portable
  • Aucun prérequis manuel nécessaire
  • Installation et désinstallation maîtrisées
  • Séparation claire entre infrastructure et configuration
